# 遊戲內物理測試球（0.3／0.7～0.10）

測試球把力轉成實際位置與速度，可用來檢查空氣、水與碰撞的接軌。
它是通用核心的測試工具，目前不能駕駛，也不代表已選定未來載具造型。
0.7 起測試球改用和平台相同的六自由度剛體與接觸求解器：會反彈、滑動、滾動，也有附加質量；0.8 加入波浪輻射阻尼。
0.9 起測試球也取樣世界波浪區域（`/aerocore waves ...`）、穿出水面時用半球繞射表，並與平台、測試船雙向碰撞；
原版實體可以站在它上面（以球內 0.7 m 立方體近似）。

## 操作

在 IntelliJ 選 **Minecraft Client** 重新啟動開發用遊戲。更新程式不會熱替換已開啟遊戲中的 Java 類別。
在單人開啟作弊，或具備伺服器指令權限 2 以上，站在空曠處並朝向前方或水面：

| 指令 | 行為 |
| --- | --- |
| `/aerocore probe spawn` | 在視線前方 3 m 生成直徑 1 m、質量 250 kg 的球 |
| `/aerocore probe spawn 1000` | 生成會在淡水中下沉的 1000 kg 球 |
| `/aerocore probe spawn 250 10` | 沿視線以 10 m/s 發射 |
| `/aerocore probe inspect` | 查看 32 m 內由你生成的最近一顆球 |
| `/aerocore probe wind 10 0 0` | 對最近的自有球設定世界 +X 方向 10 m/s 測試風 |
| `/aerocore probe current 1 0 0` | 對最近的自有球附加 +X 方向 1 m/s 水流 |
| `/aerocore probe wind 0 0 0` | 清除該球的測試風 |
| `/aerocore probe current 0 0 0` | 清除附加水流，仍讀取原版水流 |
| `/aerocore probe clear` | 移除 64 m 內由你生成的球 |

質量範圍 50～2000 kg，初速 0～30 m/s；風／附加水流各分量 −10～10 m/s。
風與水流設定只屬於那顆測試球，不會改全世界的天氣或水。
球體右鍵也能查看數據，不需要反覆輸入指令。
若前方空間不夠，生成會報錯；請朝向較空曠的位置，不會替你破壞方塊。

每個維度最多由此指令生成 32 顆已載入測試球。
球體不寫入存檔，卸載區塊／重開世界後不保留；連續模擬 12000 tick（正常 20 TPS 約10分鐘）會移除。
接近未載入區塊時停止運動，不替球體強制載入整片地圖。

## 可以觀察到什麼

在乾地上方生成：球因重力下落，受空氣阻力影響；落地會反彈，幾次後停住。0.10 起球殼視為鋼、方塊視為岩石：
恢復係數依撞擊速度用 Thornton 彈塑性撞擊律（1 m/s 約 0.47、5 m/s 約 0.31），摩擦 0.4（低碳鋼對安山岩實測）。
沿地面發射時先滑動，摩擦讓它轉起來，以初速的 5/7 純滾動；沒有滾動阻力，所以平地上會一直滾。
撞牆會彈回，不會穿過；高速時可能在牆面前 v·dt（30 m/s 時約 0.15 m）內就反彈。
在至少 3 格深、數格寬的平靜水池上方生成：250 kg 球進水後振盪，0.8 起因波浪輻射阻尼在數秒內穩定漂浮，
1000 kg 球會沉到池底。過淺的水或岸邊可能先發生碰撞，不能用來驗證自由漂浮。

半徑 0.5 m 的球排水體積約 0.5236 m³，完全浸水浮力約 5125 N。
250 kg 球的平衡浸水體積比例約 47.8%，1000 kg 球的重量則大於最大浮力。
藍色為低於完整淡水排水質量的球，橙色為較重的球；白色緯帶便於觀察水線，深色經線區塊用來看出自轉。

診斷顯示質量、速率、垂直速度、自轉角速度、浸水體積比例、浮力、重量、平均阻力（含波浪輻射力）與接觸力，都是上一 tick 的平均。
停在地面時接觸力約等於重量減浮力。

## 數值與世界接軌

- 1 方塊 = 1 m，1 模擬 tick = 0.05 s，每 tick 分成 10 個 0.005 s 小步。
- 伺服器計算物理狀態；客戶端插值伺服器傳來的位置與同步四元數，畫出旋轉。
- 球視為均質實心球：重心在球心，I = 2/5·m·R²。實體位置是球底，物理狀態位置是球心。
- 重力取 9.80665 m/s²，關閉原版額外重力和流體推力，避免重複施加。
- 受力由 `FloatingBodyDynamics` 計算，與平台的單一浮筒相同：重量、空氣與水的浮力、依雷諾數的光滑球標準阻力曲線（Clift 等 1978，0.10 起）
  （乾／濕面積按浸水比例分配，隱式求解），以及 0.5·ρ·V_wet 的附加質量；另有與平台相同的垂直波浪輻射記憶力（球的水線面半徑隨浸水而變）。
- 空氣使用相對該維度生成器海平面的標準大氣，超出模型高度時取端點值。
  這是測試用地球大氣設定，不是所有 Minecraft 維度的真實大氣模型。
- 使用實際帶 WATER 標籤的流體方塊和流體高度；海平面以下的乾燥洞穴不產生水浮力。
- 球體採 7×7 水平取樣柱，沿每條球弦累計和水的交集；用全體球弦體積正規化浸水比例。
  全浸／離水與對稱半浸水準確，岸邊與曲面部分浸水有取樣誤差；不是精確球面與所有方塊的體積布林運算。
- 原版 `FluidState.getFlow` 是無因次流向；0.10 起 1 單位取 1.12 m/s，即原版生物在滿強度水流中被推到的漂移速度，
  不是實測水速。1 m 球在 1 m/s 相對流速下 Re 約 10⁶、已過阻力危機（C_D 約 0.11），所以被水流帶動得比 0.9 慢。
- 接觸由 `ContactSolver` 處理：球對方塊碰撞盒、可碰撞實體與世界邊界做序列衝量，含庫侖摩擦、恢復係數與推測接觸。
  每 tick 收集球兩 tick 內可到達範圍的障礙；若球離開該範圍，該 tick 停止運動。障礙物不會被推動。
- 0.11 起每個方塊依材質類別（冰、木、沙、礫石、泥土、泥巴、雪、羊毛、玻璃、金屬、岩石）有自己的摩擦與恢復係數：
  鋼球在石頭上會反彈、在沙上不會，在冰上幾乎不減速。係數與來源見 [物理模型](PHYSICS.md)〈0.11 新增模型與係數來源〉。

沒有滾動阻力、旋轉造成的空氣力（Magnus 效應）或旋轉阻尼：阻力作用在球心，所以球在空中或水中會一直保持自轉。
測試球沒有熱模型，也沒有入水拍擊、波浪或空化。球不會直接執行二維 CFD，也不會改變水方塊／空氣網格。
多點浮力與完整的平台示範見 [六自由度平台](PLATFORM.md)。

## 驗證

```powershell
.\dev.ps1 :physics:test :cfd:test
.\dev.ps1 :neoforge:runGameTestServer
```

亦可在 IDEA 選 **Test Physics**、**Test Minecraft Physics**。
GameTest 使用使用者 `.mcmod/runs/aerocore/gametest/` 下的獨立測試世界，不讀取玩家的遊戲存檔。
此設定才會登錄 AeroCore 的測試案例；一般遊戲不會自動建立測試場地。

純 Java 測試涵蓋自由落體解析解、質量／衝量、二次阻力解析衰減、相對速度不變性、中性浮力、沉浮方向、
漂浮趨近平衡及受力與動量一致性；0.7 的接觸與附加質量另見 [物理模型](PHYSICS.md)。
Minecraft GameTest 驗證乾地落地靜止、30 m/s 撞牆不穿透且被彈回、沿地面發射後以 5/7 初速純滾動（滑速 < 0.05 m/s）、
輕球漂浮、重球沉底、水流推動、乾／半濕／全濕幾何取樣。
框架參考 [NeoForge 1.21.1 GameTest 文件](https://docs.neoforged.net/docs/1.21.1/misc/gametest/)。
